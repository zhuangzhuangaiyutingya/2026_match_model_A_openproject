# 评估结果说明

100 个计算图用例 × 3 个问题 × 4 档核数（2/3/4/5 核）= **1200 个评估格**。本文说明每格的评估口径、汇总结果，以及明细数据的获取与核对方式。逐格明细见 [`report/all_results.csv`](report/all_results.csv)（1200 行，每行一格）。

## 评估口径

每一格对应"某个计算图用例在某问题、某核数下的一个调度方案"，由赛题官方评估器逐周期事件模拟结算：

- **makespan**：整体完成周期数，越小越好；
- **加速比**：同一用例官方单核基线 Makespan ÷ 该格 Makespan；
- **平均加速比**（官方成绩口径）：每个"问题 × 核数"下 100 个用例加速比的算术平均；
- **新增搬运量**：因切分与核内溢出额外产生的拷贝字节，同 Makespan 下的次要参考；
- **Cache 命中率**：问题三特有，读请求命中 1MB 只读 FIFO Cache 的字节占比。

调度方案由一组切分策略（区域生长、深度窗口条带、波前条带等）分别生成，逐个经官方评估器实测后取最小 Makespan；任何策略劣于单核基线即回退单核方案，因此 1200 格全部加速比 ≥ 1。

几个值得注意的形态：

- **问题二 / 问题三的核间扩展性明显好于问题一**。场景 B 把每核任务合并、跨核只付拷贝延迟，切分可以更细；场景 A 每条跨核任务依赖付 1000 周期等待，低核数下粗粒度方案更占优，核数增加时收益增速也随之放缓。加速比最高的格是 case_084（问题二五核 6.69 倍）——并行度远超核数的宽图在场景 B 下几乎没有切分代价；
- **问题一收益最低的格集中在并行度低的小图**（如 case_064、case_069、case_071，741～1032 算子）：图自身可提取的并行度不足 10，切分后跨核等待吃掉大部分收益，这类格接近问题结构允许的上限；
- **问题三相对问题二的 Cache 收益平均 +1.09%**（177 格更优、220 格持平、3 格更差），远低于完美缓存的理论上限（约 +6%）。原因是 1MB FIFO 在两次读之间被核内溢出与跨核边界流量换空；提高 Cache 收益的前置是压低这些流量，而不是输入亲和调度（后者实测全部更差，见 [`OPTIMIZATION_NOTES.md`](../docs/OPTIMIZATION_NOTES.md) 第八节）。

三档收益接近，方法组合没有明显的规模盲区。

### 新增搬运量

全部格平均 11.24 MB、中位 1.77 MB、最大 336.7 MB（3.9 万算子大图）。中位远小于均值，说明多数格的切分与溢出代价已压得很低，搬运量大头集中在少数巨型图。

## 数据核对

全部 1200 格经官方命令行工具独立进程复放（每格留档 CLI 的输入与输出 JSON）：1189 格与评测记录完全一致；11 格存在 0.1%～1.6% 偏差，已按 CLI 存档值修正。偏差根因是 P2/P3 官方评估器跨进程非确定——同一方案不同进程的 Makespan 与新增搬运量有微差（进程内完全确定）。对外引用本文数字时，建议按 ±0.5% 理解复跑波动。

核对汇总见 [`audit_summary.json`](audit_summary.json)。

## 明细数据

`report/all_results.csv` 每行字段：

| 字段 | 含义 |
|---|---|
| case | 用例名（case_001～case_100） |
| problem | 问题编号 1/2/3 |
| cores | 核数 2/3/4/5 |
| singlecore_makespan | 官方单核基线 Makespan |
| makespan | 本格最优方案的 Makespan |
| speedup | singlecore_makespan ÷ makespan |
| added_copy_bytes | 切分与溢出的新增拷贝字节 |
| label | 生成该方案的切分策略与参数 |
| cache_hit_rate | 问题三的 Cache 命中字节率（问题一/二为 0） |
| parallelism, n_elig | 用例的图并行度与合格算子数 |

上表所有统计都可以直接对这份 CSV 分组重算。
