## 算法概述（论文可用的表述框架）

### 代价模型
把原图 G 中非 COPY_IN/COPY_OUT 的算子集合记为 V（评测口径的"核内算子"），
收缩 COPY 节点得到算子 DAG。对任一划分（算子 -> 子图/Task），
按评估器的边界搬运规则精确计算**新增 DDR 搬运量**：
- 图输入张量：每个消费 Task 各读一次（重复读惩罚）；
- 中间张量：有外部消费者时生产侧 COPY_OUT 一次 + 每个外部消费 Task COPY_IN 一次；
- 原图输出张量：生产 Task COPY_OUT 与基线一致，不新增。
场景 B 同口径按"核"聚合（同核合并 Task，跨核边付 2 倍张量字节 + 500 周期）。

### 切图：区域生长 + FM 精化 + 环守卫
1. **区域生长**：种子取剩余向上工作量最大者；邻居按"通信收益/工作量"
   （连接张量字节 + 共享图输入去重收益）入优先队列贪心生长，
   至目标工作量（总工作量 × (1+slack) / 子图数）。复杂度 O((V+E)·log V)。
2. **FM 精化**：边界算子在相邻簇间移动，目标 = 新增搬运量下降，
   约束 = 目标簇负载不超过 (1+tol)·平均；多轮至无改进。
3. **环守卫**：增量维护任务图边计数，移动前后 BFS 判定是否引入任务环
   （任务图必须保持 DAG，否则方案非法）。
4. **无环兜底**：精化后仍成环则回退仅生长；再成环回退深度横切
   （按 (深度, 拓扑序) 切分，数学上保证无环）。

### 调度：通信感知列表调度（HEFT 简化）
Task 代价 = max(M 分量, V 分量) + 1.5×预估换入换出字节/带宽；
向上 rank 递推含通信与等待。按"拓扑约束下的优先序"（Kahn + rank 堆）调度：
- 场景 A：同核前驱 +100 周期、跨核前驱 +1000 周期 + 搬运时间；
- 场景 B：同核零成本、跨核 +500 周期 + 搬运时间。
择核目标 = 最早完成时刻（平分时取轻载核）。

### 结构调度候选（v9）
参数族切分对深依赖图、巨型 UB 工作集图和超宽图会退化，为此按图特征门控引入
三个结构候选（`structural_scheduler.py`，依赖/通信分离建模，含 8 项回归测试）：
1. **波前条带（wavefront）**：按拓扑深度分窗，窗内用 (M,V) 双维 LPT 分 lane，
   lane 固定映射到核。针对深依赖宽波前图（如 c003 类），P2/P3 曾取得 72%~157% 提升。
2. **宽图分摊（wide）**：逐层 LPT 强制所有核获得近量工作，修复
   "高并行度却整体留在单核"的退化（如 c084/095/028 类）。
3. **fork-join lane 保持**：自动识别"广播 → 多路独立短链 → 归约树"的重复阶段
   （结构推导，不依赖用例名/ID），lane 跨阶段固定同核，归约节点跟随最重前驱。
   针对巨型 UB 总量但单阶段工作集小的图（如 c016 类），P2/P3 取得 84%~220% 提升。

### 深度窗口条带（bandcomp，v32–v35）

对深而稀疏的图（深度 138~460、层内大量弱连通分量），按深度切窗口、
窗内取弱连通分量——分量间互无边（定义保证），窗口间边只会从浅指向深，
**任务图天然无环**。分量按 max(M,V) 工作量 LPT 装核，带前驱粘性
（优先跟随前驱分量所在核，减少跨核等待）；再叠加 FM 精化降低窗口
边界切分流量。窗口宽度与粘性系数经全网格扫描（w=2~32 × sticky
0.25/0.5/1.0/2.0）。在最终结果里，1200 格中约 900 格（75%）由这一族方案胜出。

**伴随修复**：区域生长在链/弱连通图上原存在"前沿耗尽即停止"缺陷
（98% 算子落入散射兜底，宽图全核数 S=1.0），v31 改为前沿耗尽时
换新种子继续装填（reseed），旧行为保留为 grow_ns 候选并列。

**跨问题交叉**（v36）：方案格式跨问题通用，每个问题的赢家方案在其他
问题的官方评估器下免费重评，采纳更优者（+59 格）。

### 候选搜索与保底
每个 (用例, 问题, 核数) 的候选 = 参数族网格 ∪ 特征门控的结构候选：
- 小图（≤1500 算子）：粒度全档扫描（mult 1~8 × 均衡容差两档）；
- 中图（≤9000）：基础档 + 五核专项 m3/4/5/6/8 + tol 0.15；
- 大图：粗粒度档 + 结构候选；
- 全部候选经官方评估器实测，取 Makespan 最小者（近似平局时参考新增搬运量）；
- **严格单核保底**：任何候选劣于单核基线即启用合法单核方案
  （P2 与单核严格同构；P3 由官方评估器实测，有时因 Cache 略优于基线），
  保证 1200 格全部 S ≥ 1。

### 问题 3（只读 L2 Cache）
沿用问题 2 的方案空间；L2 命中由评估器按逻辑张量 id 的 FIFO 规则结算，
命中率随方案输出，用于对比分析。

## 复现步骤
```bash
cd my_solution
# 1) 全量实验（支持断点续跑；小图秒级、3 万算子大图单格可达数十分钟，
#    建议 --cases 分片并行，或参考 run_cells.py 按 (用例,问题,核数) 拆分）
python run_experiments.py --full
# 2) 生成报告（从榜单分片合成，与 LEADERBOARD.md 同源）
python make_report.py
# 3) 用官方 CLI 复现任一最优方案（示例）
python replay_official.py case_001 1 4     # 用例 问题 核数
# 4) 结构模块改动后运行回归测试
python -m unittest discover -s tests
```
`replay_official.py` 内部调用赛题提供的
`multicore_cut_evaluate_problem_{1,2,3}.py` 与 `config.txt`（未做任何修改），
输出官方格式的 res / trace / log 三件套。

## 算法运行时间口径

- 候选搜索为 portfolio 式：每格生成候选集（参数族 + 结构族 + 条带族，
  按图规模分档），逐个经官方评估器实测取最小 Makespan；
- 官方 CLI 单格复评实测：1200 格合计 2.8 小时（平均 8.3 秒/格，
  最慢单格 case_091|p1|k2 183 秒），64 核服务器 44 并发约 40 分钟；
- 六轮批量优化（v31–v36）服务器端累计约 17 小时（44 并发），
  审计 1 小时；本地开发机全程可复现（仅标准库 + matplotlib）。
