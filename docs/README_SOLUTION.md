# 算法与复现说明

本仓库的求解代码在 `src/`，赛题附件（计算图用例 `data/`、官方评估器 `code/`）请从竞赛官方渠道获取并放到与 `src/` 平级的位置（版权归主办方，仓库不收录）。本文说明算法结构、模块划分与从零复现结果的完整数据流。

## 算法概述

### 代价模型

图模型把原始图收缩成"合格算子"视图：COPY 节点收缩进边，直接 op→op 依赖保留为零字节边；每算子记录所属流水线（PIPE_M / PIPE_V）的工作量、输入张量的生产者集合；每个切分簇维护 M / V 双维负载、向上 rank 与深度。任务图合法性（无环、同核顺序）一律使用收缩后的完整依赖——零字节边同样能构成环。

### 切分：区域生长 + FM 精化（含补种）

区域生长以"剩余向上工作量最大"为种子、按通信收益/工作量比吸收邻居，簇到达目标额即止；FM 精化在簇间搬动算子改善切边；再均衡修正负载倾斜。链状/弱连通图上生长前沿会提前耗尽，若不处理会有 98% 算子落入就近散射、破坏均衡并撕出大张量跨核拷贝——实现里在前沿耗尽且未达目标额时换新种子继续装填（补种），旧行为保留为独立变体，两种行为进入候选集逐格实测取优。

### 切分：深度窗口 × 连通分量条带（bandcomp）

按深度切窗口、窗内取弱连通分量：分量间无边（定义保证），窗口间边只从浅指向深，任务图天然无环。分量按 max(M, V) 工作量 LPT 装核，带前驱粘性（优先跟随前驱分量所在核，减少跨核等待），再叠加 FM 精化压缩窗口边界的切分流量。窗口宽度与粘性系数是主要调参维度，按图规模分档取值。

### 结构候选

深依赖宽波前图用波前条带（同层 M/V 双维均衡切 lane）；并行度远超核数的宽图用强制分摊；重复 fork-join 结构用阶段模板。仅在触发形态条件的图上加入候选集。

### 调度

通信感知列表调度（HEFT 简化）：按向上 rank（含通信）定优先级，逐任务选最早完工的核；同核前驱 +100 周期、跨核 +1000（场景 A）或 +500 拷贝延迟（场景 B）。核内 spill（UB 128KB / L1 512KB 换入换出）由官方评估器结算，调度侧通过簇工作集估计参与 rank。

### 择优与保底

每个格（用例 × 问题 × 核数）的候选集按图规模分档组合，全部经官方评估器实测取最小 Makespan；任何候选劣于单核基线即回退单核方案。三个问题的方案格式通用，赢家方案会交叉到其他问题的评估器下重评，更优则采纳。

## 从零复现

前置：Python 3.8+（实验仅标准库；绘图需 matplotlib）；赛题附件 `data/` 与 `code/` 放到仓库根目录。

```bash
# 1) 全量实验：生成候选 -> 官方评估器打分 -> 逐格择优
#    （支持断点续跑；小图秒级、3.9 万算子大图单格可达数十分钟，建议按 --cases 分片并行）
python src/run_experiments.py --full

# 2) 汇总为逐格明细 CSV 与图表
python src/make_report.py

# 3) 校验结果（覆盖 1200 格、数值一致性；默认严格，发现问题以非零退出）
python src/validate_results.py

# 4) 官方 CLI 逐格复放审计（可选；单格 0.5 秒~3 分钟，1200 格合计约 2.8 小时）
python src/run_audit.py --jobs 8
```

数据流：`run_experiments.py` 逐格把最优方案与指标写入结果记录；`make_report.py` 汇总为 `all_results.csv`；`validate_results.py` 以这份 CSV 为单一数据源做覆盖与一致性校验；`run_audit.py` 用官方 CLI 独立进程复核每一格并生成审计汇总。仓库 `results/` 下提交的正是这套流程产出的最终快照（含 1200 个最优方案 `results/best_plans/`）。

## 运行时间口径

候选搜索为 portfolio 式，逐候选经官方评估器实测。官方 CLI 单格复评实测：1200 格合计约 2.8 小时（平均 8.3 秒/格，最慢单格 183 秒），64 核机器 44 并发约 40 分钟。

## 已知特性

P2/P3 官方评估器存在跨进程非确定性：同一方案在不同进程中的 Makespan 与新增搬运量有 0.1%～1.6% 的运行间微差（同一进程内完全确定；与 PYTHONHASHSEED 无关，为 Linux Python 3.8 运行间行为）。对比实验应在同一进程内完成，或对多次独立运行取中位。
